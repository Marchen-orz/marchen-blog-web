## JavaScript 数组方法对比表

| 方法          | 作用描述                                                     | 返回值类型           | 是否修改原数组             | 备注                                                    |
| ------------- | ------------------------------------------------------------ | -------------------- | -------------------------- | ------------------------------------------------------- |
| **forEach**   | 遍历数组元素，对每个元素执行回调函数                         | `undefined`          | 否（但可通过索引间接修改） | 无法用 `break` 中断遍历                                 |
| **map**       | 遍历数组元素，根据回调返回值生成新数组                       | **新数组**           | 否                         | 适合数据转换（如数值翻倍、对象格式转换）                |
| **filter**    | 筛选满足条件的元素，返回新数组                               | **新数组**           | 否                         | 新数组长度 ≤ 原数组                                     |
| **reduce**    | 通过回调函数累积计算结果（从左到右）                         | 任意类型（累积结果） | 否                         | 可设置初始值（如 `arr.reduce(callback, initialValue)`） |
| **some**      | 检查数组中是否**至少有一个元素**满足条件                     | **布尔值**           | 否                         | 遇到第一个 `true` 立即返回，类似逻辑或                  |
| **every**     | 检查数组中是否**所有元素**都满足条件                         | **布尔值**           | 否                         | 遇到第一个 `false` 立即返回，类似逻辑与                 |
| **find**      | 返回第一个满足条件的元素                                     | 元素或 `undefined`   | 否                         | 替代 `indexOf` 的对象查找场景                           |
| **findIndex** | 返回第一个满足条件的元素索引                                 | 数字（索引或 `-1`）  | 否                         | 对象版 `indexOf`                                        |
| **flatMap**   | 对数组中的每个元素应用回调函数，然后将结果展开一级，返回新数组 | 新数组               | 否                         | 相当于 `arr.map(...args).flat(1)`，但更高效             |

## 媒体查询

媒体查询的基本语法如下：

```css
@media media-type and (media-feature) {

 /* 样式规则 */

}
```

- **`@media`** ：声明这是一个媒体查询。
- **`media-type`** ：指定媒体类型，例如 `screen`（屏幕）、`print`（打印）、`all`（所有设备）等。
- **`media-feature`** ：指定媒体特性，例如屏幕宽度、高度、分辨率等。

### 常见的媒体特性

媒体查询支持多种媒体特性，以下是一些常用的属性及其含义：

#### 宽度相关

- `width`：视口宽度。
- `min-width`：最小视口宽度。
- `max-width`：最大视口宽度。

**示例：**

```css
@media screen and (min-width: 768px) and (max-width: 1024px) {
    /* 当屏幕宽度在 768px 到 1024px 之间时生效 */
}
```

#### 高度相关

- `height`：视口高度。
- `min-height`：最小视口高度。
- `max-height`：最大视口高度。

#### 方向

- `orientation`：设备的方向，值可以是 `portrait`（纵向）或 `landscape`（横向）。

**示例：**

```css
@media screen and (orientation: landscape) {
    /* 当设备处于横屏模式时生效 */
}
```

#### 分辨率

- `resolution`：设备的像素密度。
- `min-resolution` 和 `max-resolution`：最小和最大像素密度。

**示例：**

```css
@media screen and (min-resolution: 2dppx) {
    /* 针对高分辨率屏幕（如 Retina 显示器） */
}
```

#### 其他

- `aspect-ratio`：视口的宽高比。
- `hover`：是否支持悬停（如鼠标悬停效果）。
- `pointer`：主要输入设备的精度（如 `fine` 表示高精度，`coarse` 表示低精度）。

### 逻辑运算符

媒体查询支持逻辑运算符，用于组合多个条件：

#### `and`：同时满足多个条件

**示例：**

```css
@media screen and (min-width: 600px) and (max-width: 1200px) {
    /* 屏幕宽度在 600px 到 1200px 之间 */
}
```

#### `,`（逗号）：表示“或”关系

**示例：**

```css
@media screen and (max-width: 600px), print {
    /* 屏幕宽度小于 600px 或者打印时生效 */
}
```

#### `not`：取反

**示例：**

```css
@media not screen and (max-width: 600px) {
    /* 不是屏幕设备或者屏幕宽度大于 600px 时生效 */
}
```

#### `only`：仅适用于特定设备

**示例：**

```css
@media only screen and (max-width: 600px) {
    /* 仅在屏幕设备上生效 */
}
```

### 1. **`fs` 模块（文件系统模块）**

#### 异步方法：

- `fs.readFile(path, [options], callback)`：异步读取文件内容。
- `fs.writeFile(file, data, [options], callback)`：异步写入文件。
- `fs.appendFile(file, data, [options], callback)`：异步追加内容到文件。
- `fs.unlink(path, callback)`：异步删除文件。
- `fs.mkdir(path, [options], callback)`：异步创建目录。
- `fs.rmdir(path, callback)`：异步删除目录。
- `fs.readdir(path, [options], callback)`：异步读取目录内容。
- `fs.stat(path, callback)`：异步获取文件或目录的状态信息。

#### 同步方法：

- `fs.readFileSync(path, [options])`：同步读取文件内容。
- `fs.writeFileSync(file, data, [options])`：同步写入文件。
- `fs.appendFileSync(file, data, [options])`：同步追加内容到文件。
- `fs.unlinkSync(path)`：同步删除文件。
- `fs.mkdirSync(path, [options])`：同步创建目录。
- `fs.rmdirSync(path)`：同步删除目录。
- `fs.readdirSync(path, [options])`：同步读取目录内容。
- `fs.statSync(path)`：同步获取文件或目录的状态信息。

### 3. **`path` 模块（路径处理模块）**

- `path.resolve([...paths])`：同步解析路径为绝对路径。
- `path.basename(path, [ext])`：同步获取路径的最后一部分（文件名）。
- `path.dirname(path)`：同步获取路径的目录部分。
- `path.extname(path)`：同步获取路径的扩展名。

### 4. **`os` 模块（操作系统模块）**

#### 同步方法：

- `os.platform()`：同步返回操作系统平台。
- `os.arch()`：同步返回操作系统架构。
- `os.cpus()`：同步返回CPU信息。
- `os.freemem()`：同步返回系统空闲内存。
- `os.totalmem()`：同步返回系统总内存。
- `os.homedir()`：同步返回当前用户的主目录。

### 5. **`child_process` 模块（子进程模块）**

#### 异步方法：

- `child_process.exec(command[, options], callback)`：异步执行shell命令。
- `child_process.spawn(command[, args][, options])`：异步启动子进程执行命令。
- `child_process.fork(modulePath[, args][, options])`：异步启动一个新的Node.js进程。

#### 同步方法：

- `child_process.execSync(command[, options])`：同步执行shell命令。
- `child_process.spawnSync(command[, args][, options])`：同步启动子进程执行命令。

### 6. **`stream` 模块（流模块）**

#### 异步方法：

- `stream.Readable`：可读流（异步读取数据）。
- `stream.Writable`：可写流（异步写入数据）。
- `stream.Duplex`：双工流（可读可写）。
- `stream.Transform`：转换流（在读写过程中可以修改数据）。
- `stream.pipeline(source, [...transforms], destination, callback)`：异步管道流处理。

### **2. Composition API 的标准用法**

#### **(1) `setup` 函数**
- **作用**：替代 Options API 中的 `data`、`methods`、`computed` 等选项。
- **示例**：
  ```javascript
  import { ref, computed } from "vue";
  
  export default {
      setup() {
          const count = ref(0);
          const doubleCount = computed(() => count.value * 2);
  
          function increment() {
              count.value++;
          }
  
          return { count, doubleCount, increment };
      },
  };
  ```

#### **(2) 响应式数据**
- 使用 `ref` 和 `reactive` 创建响应式数据。
- **`ref`**：适用于基本类型或单个值。
  ```javascript
  const name = ref("Vue");
  ```
- **`reactive`**：适用于对象或数组。
  ```javascript
  const state = reactive({ name: "Vue", version: 3 });
  ```

#### **(3) 计算属性**
- 使用 `computed` 创建依赖其他数据的动态值。
  ```javascript
  const fullName = computed(() => `${firstName.value} ${lastName.value}`);
  ```

#### **(4) 方法定义**
- 在 `setup` 中定义方法，并通过 `return` 暴露给模板。
  ```javascript
  function greet() {
      alert(`Hello, ${name.value}!`);
  }
  return { greet };
  ```

### **3. 生命周期钩子的标准用法**

Vue 3 提供了组合式生命周期钩子，需要从 `vue` 中导入。

| Options API    | Composition API | 描述               |
| -------------- | --------------- | ------------------ |
| `beforeCreate` | 不需要          | `setup` 替代       |
| `created`      | 不需要          | `setup` 替代       |
| `mounted`      | `onMounted`     | 组件挂载完成后调用 |
| `updated`      | `onUpdated`     | 组件更新后调用     |
| `unmounted`    | `onUnmounted`   | 组件卸载时调用     |

##### **示例**
```javascript
import { onMounted, onUnmounted } from "vue";

export default {
    setup() {
        onMounted(() => {
            console.log("Component mounted");
        });

        onUnmounted(() => {
            console.log("Component unmounted");
        });
    },
};
```

### `ref`与 `reactive` 的区别

虽然数组可以用 `ref`，但在某些情况下，使用 `reactive` 可能更合适。以下是两者的对比：

| 特性         | `ref`                  | `reactive`                     |
| ------------ | ---------------------- | ------------------------------ |
| **适用范围** | 基本类型和引用类型     | 仅适用于引用类型（对象、数组） |
| **访问方式** | 需要通过`.value`访问   | 直接访问属性，无需`.value`     |
| **推荐场景** | 单个变量或简单数据结构 | 复杂对象或嵌套数据结构         |

### 对比 `ref` 和 `computed` 的行为

| 特性           | `ref`                  | `computed`                       |
| -------------- | ---------------------- | -------------------------------- |
| **定义方式**   | `const count = ref(0)` | `const fullName = computed(...)` |
| **模板中使用** | 不需要`.value`         | 不需要`.value`                   |
| **脚本中使用** | 需要`.value`           | 需要`.value`                     |
| **是否可写**   | 可以直接修改`.value`   | 默认只读，不能直接修改           |

### Vue3中的语法糖

在Vue3中，**语法糖**（Syntax Sugar）是指通过更简洁、直观的语法来实现某些功能。Vue3引入了许多新的特性，比如`<script setup>`和`defineProps`/`defineEmits`等，这些特性大大简化了代码书写方式，提升了开发体验。

以下我们将围绕Vue3中的**语法糖**展开讲解，重点包括以下几个方面：
1. `<script setup>`语法糖
2. `defineProps`和`defineEmits`的使用
3. 插槽相关的语法糖

---

#### 1、`<script setup>`语法糖

`<script setup>`是Vue3中专门为单文件组件（SFC）设计的语法糖，它简化了组件的定义和逻辑编写，无需手动导出默认对象。使用`<script setup>`后，组件的所有内容都被视为自动暴露给模板。

##### **特点：**
- 不需要显式地写`export default`。
- 所有的变量、函数和导入的内容都可以直接在模板中使用。
- 更适合组合式API（Composition API）的使用场景。

**基本用法：**

```vue
<script setup>
import { ref } from 'vue';

const count = ref(0);

function increment() {
  count.value++;
}
</script>

<template>
  <div>
    <p>当前计数: {{ count }}</p>
    <button @click="increment">增加</button>
  </div>
</template>
```

**对比传统写法：**
在传统的`<script>`写法中，我们需要显式地导出一个对象，并将变量和方法挂载到`setup`函数返回的对象上：

```vue
<script>
import { ref } from 'vue';

export default {
  setup() {
    const count = ref(0);

    function increment() {
      count.value++;
    }

    return { count, increment };
  }
};
</script>

<template>
  <div>
    <p>当前计数: {{ count }}</p>
    <button @click="increment">增加</button>
  </div>
</template>
```

可以看到，`<script setup>`让代码更加简洁明了。

---

#### 2、`defineProps`和`defineEmits`

在使用`<script setup>`时，Vue3还提供了两个内置函数：`defineProps`和`defineEmits`，用于定义组件的`props`和自定义事件。它们是专门针对`<script setup>`设计的语法糖，进一步简化了父子组件通信的代码。

##### 1. `defineProps`
`defineProps`用于声明组件接收的`props`，其语法比传统的`props`选项更简洁。

**示例代码：**

```vue
<script setup>
// 定义props
const props = defineProps({
  title: String,
  likes: Number
});
</script>

<template>
  <div>
    <h1>{{ title }}</h1>
    <p>点赞数: {{ likes }}</p>
  </div>
</template>
```

**等价的传统写法：**

```vue
<script>
export default {
  props: {
    title: String,
    likes: Number
  }
};
</script>

<template>
  <div>
    <h1>{{ title }}</h1>
    <p>点赞数: {{ likes }}</p>
  </div>
</template>
```

##### 2. `defineEmits`
`defineEmits`用于声明组件可以触发的自定义事件，替代了传统的`emits`选项。

**示例代码：**

```vue
<script setup>
// 定义触发事件
const emit = defineEmits(['update', 'delete']);

function handleUpdate() {
  emit('update', '更新的数据');
}

function handleDelete() {
  emit('delete', '删除的数据');
}
</script>

<template>
  <div>
    <button @click="handleUpdate">更新</button>
    <button @click="handleDelete">删除</button>
  </div>
</template>
```

**等价的传统写法：**

```vue
<script>
export default {
  emits: ['update', 'delete'],
  methods: {
    handleUpdate() {
      this.$emit('update', '更新的数据');
    },
    handleDelete() {
      this.$emit('delete', '删除的数据');
    }
  }
};
</script>

<template>
  <div>
    <button @click="handleUpdate">更新</button>
    <button @click="handleDelete">删除</button>
  </div>
</template>
```

**总结：**
- `defineProps`和`defineEmits`是专门为`<script setup>`设计的语法糖，简化了`props`和`emits`的定义。
- 它们不需要显式地写在`export default`中，直接在`<script setup>`中使用即可。

#### 3、插槽相关的语法糖

Vue3对插槽也提供了一些语法糖，特别是在具名插槽和作用域插槽的使用上。

##### 1. 具名插槽的简写
Vue3支持使用`#`符号作为`v-slot`的简写形式。

**传统写法：**

```vue
<template>
  <Child>
    <template v-slot:header>
      <h1>头部内容</h1>
    </template>
    <template v-slot:footer>
      <p>底部内容</p>
    </template>
  </Child>
</template>
```

**语法糖写法：**

```vue
<template>
  <Child>
    <template #header>
      <h1>头部内容</h1>
    </template>
    <template #footer>
      <p>底部内容</p>
    </template>
  </Child>
</template>
```

##### 2. 作用域插槽的简写
在作用域插槽中，Vue3允许直接解构插槽传递的数据。

**传统写法：**

```vue
<template>
  <Child v-slot="slotProps">
    <p>用户名: {{ slotProps.user.name }}</p>
    <p>年龄: {{ slotProps.user.age }}</p>
  </Child>
</template>
```

**语法糖写法：**

```vue
<template>
  <Child v-slot="{ user }">
    <p>用户名: {{ user.name }}</p>
    <p>年龄: {{ user.age }}</p>
  </Child>
</template>
```

**总结：**
- 使用`#`代替`v-slot`可以让代码更简洁。
- 解构插槽数据可以直接在`v-slot`中完成，避免了繁琐的对象访问。

## Fetch用法

### **1. 基本用法**

#### 语法
```javascript
fetch(url, options)
  .then(response => {
    // 处理响应
    return response.json(); // 将响应解析为 JSON 格式
  })
  .then(data => {
    // 处理解析后的数据
    console.log(data);
  })
  .catch(error => {
    // 捕获错误
    console.error('Error:', error);
  });
```

- **`url`**：请求的目标地址（字符串）。
- **`options`**（可选）：一个配置对象，用于指定请求方法、请求头、请求体等信息。

---

### **2. 参数详解**

#### **(1) URL**
目标资源的地址，可以是相对路径或绝对路径。例如：
```javascript
fetch('/api/data'); // 相对路径
fetch('https://example.com/api/data'); // 绝对路径
```

#### **(2) Options**
`options` 是一个可选的配置对象，常用的属性包括：

- **`method`**：HTTP 请求方法，如 `GET`、`POST`、`PUT`、`DELETE` 等。
- **`headers`**：请求头，通常是一个对象，用于设置内容类型或其他自定义头部。
- **`body`**：请求体，通常用于 `POST` 或 `PUT` 请求，发送数据到服务器。
- **`mode`**：请求模式，如 `cors`、`no-cors`、`same-origin`。
- **`credentials`**：是否携带凭据（如 cookies），可选值为 `omit`、`same-origin`、`include`。

#### 示例：POST 请求
```javascript
fetch('https://example.com/api/data', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: 'Alice',
    age: 25
  })
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));
```

---

### **3. 响应处理**

`fetch` 返回一个 Promise，该 Promise 在请求完成后解析为一个 `Response` 对象。`Response` 对象提供了多种方法来处理响应数据：

- **`response.text()`**：将响应体解析为文本。
- **`response.json()`**：将响应体解析为 JSON 对象。**（返回的是promise）**
- **`response.blob()`**：将响应体解析为二进制数据（Blob 对象）。
- **`response.arrayBuffer()`**：将响应体解析为 ArrayBuffer。
- **`response.formData()`**：将响应体解析为 FormData 对象。

#### 示例：获取文本数据
```javascript
fetch('https://example.com/text')
  .then(response => response.text())
  .then(text => console.log(text))
  .catch(error => console.error('Error:', error));
```

---

### **4. 错误处理**

`fetch` 只会在网络层面失败时（如无法连接到服务器）触发 `.catch()`，而不会因为 HTTP 状态码（如 404 或 500）触发错误。因此，需要手动检查 `response.ok` 属性。

#### 示例：处理 HTTP 错误
```javascript
fetch('https://example.com/api/data')
  .then(response => {
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    return response.json();
  })
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));
```

---

### **5. 常见场景**

#### **(1) GET 请求**
```javascript
fetch('https://example.com/api/data')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));
```

#### **(2) POST 请求**
```javascript
fetch('https://example.com/api/data', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: 'Alice',
    age: 25
  })
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));
```

#### **(3) 文件上传**
```javascript
const formData = new FormData();
formData.append('file', fileInput.files[0]);

fetch('https://example.com/upload', {
  method: 'POST',
  body: formData
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));
```

---

### **6. 注意事项**

#### **(1) 默认不带 Cookies**

`fetch` 默认不会发送或接收 cookies。如果需要携带 cookies，必须设置 `credentials: 'include'`：
```javascript
fetch('https://example.com/api/data', {
  credentials: 'include'
});
```

#### **(2) 不支持超时**

`fetch` 本身不支持超时控制。如果需要实现超时功能，可以通过 `Promise.race` 实现：
```javascript
const fetchWithTimeout = (url, options, timeout = 5000) => {
  return Promise.race([
    fetch(url, options),
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error('Request timed out')), timeout)
    )
  ]);
};

fetchWithTimeout('https://example.com/api/data', {}, 5000)
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));
```

#### **(3) 不支持取消请求**
`fetch` 不支持直接取消请求。如果需要取消请求，可以使用 `AbortController`：
```javascript
const controller = new AbortController();
const signal = controller.signal;

fetch('https://example.com/api/data', { signal })
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => {
    if (error.name === 'AbortError') {
      console.log('Fetch aborted');
    } else {
      console.error('Error:', error);
    }
  });

// 取消请求
controller.abort();
```

Pinia 是 Vue 3 的官方状态管理库，它提供了一种简单、直观的方式来管理全局状态。相比 Vuex，Pinia 更加轻量、灵活，并且完全基于 Composition API 设计，非常适合 Vue 3 项目。

以下是 Pinia 的详细用法和核心概念：

---

## Pinia用法

### **1. 安装 Pinia**

首先需要安装 Pinia：
```bash
npm install pinia
```

然后在项目的入口文件（如 `main.js`）中注册 Pinia：
```javascript
import { createApp } from "vue";
import { createPinia } from "pinia";
import App from "./App.vue";

const app = createApp(App);
const pinia = createPinia();

app.use(pinia); // 注册 Pinia
app.mount("#app");
```

---

### **2. 核心概念**

Pinia 的核心概念包括以下几个部分：

#### **(1) Store**
- Store 是一个容器，用于存储全局状态。
- 每个 Store 都是一个独立的模块，可以包含状态（state）、操作（actions）和计算属性（getters）。

#### **(2) State**
- State 是 Store 中的状态数据，类似于 Vue 组件中的 `data`。
- 它是响应式的，可以直接在组件中使用。

#### **(3) Getters**
- Getters 是 Store 中的计算属性，类似于 Vue 组件中的 `computed`。
- 它用于从 State 中派生出新的值。

#### **(4) Actions**
- Actions 是 Store 中的方法，用于执行异步或复杂的逻辑。
- 它可以修改 State 或调用其他 Actions。

---

### **3. 创建 Store**

#### **(1) 定义 Store**
使用 `defineStore` 函数定义一个 Store。每个 Store 需要一个唯一的 ID 和一个配置对象。

示例：创建一个简单的计数器 Store

```javascript
// src/stores/counter.js
import { defineStore } from "pinia";

export const useCounterStore = defineStore("counter", {
    state: () => ({
        count: 0,
    }),
    getters: {
        doubleCount: (state) => state.count * 2, // 计算属性
    },
    actions: {
        increment() {
            this.count++; // 修改状态
        },
        async fetchData() {
            // 异步操作
            const response = await fetch("https://api.example.com/data");
            const data = await response.json();
            this.count = data.value; // 更新状态
        },
    },
});
```

#### **(2) 使用 Store**
在组件中通过 `useCounterStore` 使用 Store。

示例：在组件中使用 Store

```javascript
<template>
  <div>
    <p>Count: {{ counter.count }}</p>
    <p>Double Count: {{ counter.doubleCount }}</p>
    <button @click="counter.increment">Increment</button>
  </div>
</template>

<script>
import { useCounterStore } from "../stores/counter";

export default {
  setup() {
    const counter = useCounterStore(); // 使用 Store

    return { counter };
  },
};
</script>
```

---

### **4. 状态管理**

#### **(1) 访问 State**
State 是响应式的，可以直接在模板中使用。

示例：

```javascript
<p>Count: {{ counter.count }}</p>
```

#### **(2) 修改 State**
可以通过直接赋值或通过 Actions 修改 State。


通过 Actions 修改：


### **6. Actions**

Actions 是 Store 中的方法，用于执行异步或复杂的逻辑。

示例：定义和使用 Actions

### **7. 多模块 Store**

Pinia 支持多模块设计，每个模块是一个独立的 Store。

示例：创建多个 Store



## `call`、`apply` 和 `bind` 的核心区别

| **方法**  | **是否立即调用** | **参数形式**         | **返回值**             |
| --------- | ---------------- | -------------------- | ---------------------- |
| **call**  | 是               | 参数列表（逗号分隔） | 函数执行结果           |
| **apply** | 是               | 参数数组（单个数组） | 函数执行结果           |
| **bind**  | 否               | 参数列表（逗号分隔） | 返回绑定`this`的新函数 |

## **一、`ref` 相关的函数**

### 1. **`ref`**
- **作用**：创建一个响应式的引用对象，适用于基本类型和复杂对象。
- **语法**：
  ```javascript
  const count = ref(0); // 基本类型
  const obj = ref({ name: 'Vue' }); // 复杂对象
  ```
- **特点**：
  - 访问值时需要通过 `.value`。
  - 在模板中会自动解包 `.value`。

---

### 2. **`unref`**
- **作用**：解包 `ref` 类型的值。如果传入的是 `ref`，返回其 `.value`；否则直接返回原值。
- **语法**：
  ```javascript
  const value = unref(maybeRef);
  ```
- **场景**：简化对可能为 `ref` 的值的处理逻辑。
- **示例**：
  ```javascript
  const count = ref(5);
  console.log(unref(count)); // 输出: 5
  console.log(unref(10));    // 输出: 10
  ```

---

### 3. **`isRef`**
- **作用**：判断某个值是否是 `ref`。
- **语法**：
  ```javascript
  const isRefValue = isRef(value);
  ```
- **场景**：在需要明确区分 `ref` 和普通值时使用。
- **示例**：
  ```javascript
  const count = ref(0);
  console.log(isRef(count)); // 输出: true
  console.log(isRef(42));    // 输出: false
  ```

---

### 4. **`toRef`**
- **作用**：从一个响应式对象中提取某个属性，并将其转换为 `ref`。
- **语法**：
  ```javascript
  const countRef = toRef(reactiveObject, 'propertyName');
  ```
- **特点**：
  - 提取的 `ref` 仍然保持与原始对象的响应式关联。
- **场景**：当需要单独操作某个属性时使用。
- **示例**：
  ```javascript
  const state = reactive({ count: 0 });
  const countRef = toRef(state, 'count');
  
  console.log(countRef.value); // 输出: 0
  countRef.value++;
  console.log(state.count);    // 输出: 1
  ```

---

### 5. **`toRefs`**
- **作用**：将一个响应式对象的所有属性转换为 `ref`。
- **语法**：
  ```javascript
  const refs = toRefs(reactiveObject);
  ```
- **特点**：
  - 每个属性都变成独立的 `ref`，但仍与原始对象保持响应式关联。
- **场景**：在解构响应式对象时，保留响应性。
- **示例**：
  ```javascript
  const state = reactive({ count: 0, name: 'Vue' });
  const { count, name } = toRefs(state);
  
  console.log(count.value); // 输出: 0
  console.log(name.value);  // 输出: 'Vue'
  
  count.value++;
  console.log(state.count); // 输出: 1
  ```

---

## **二、`reactive` 相关的函数**

### 1. **`reactive`**
- **作用**：创建一个深层响应式的对象，适用于复杂数据结构（如对象、数组）。
- **语法**：
  ```javascript
  const state = reactive({ count: 0, user: { name: 'Vue' } });
  ```
- **特点**：
  - 所有嵌套属性都会自动变为响应式。
  - 不支持基本类型（如数字、字符串）。
- **场景**：管理复杂的状态对象。

---

### 2. **`isReactive`**
- **作用**：判断某个值是否是由 `reactive` 创建的响应式对象。
- **语法**：
  ```javascript
  const isReactiveValue = isReactive(value);
  ```
- **场景**：在需要明确区分响应式对象和普通对象时使用。
- **示例**：
  ```javascript
  const state = reactive({ count: 0 });
  console.log(isReactive(state)); // 输出: true
  console.log(isReactive({}));    // 输出: false
  ```

---

### 3. **`shallowReactive`**
- **作用**：创建一个浅层响应式的对象，仅顶层属性是响应式的。
- **语法**：
  ```javascript
  const state = shallowReactive({ count: 0, user: { name: 'Vue' } });
  ```
- **特点**：
  - 只有顶层属性是响应式的，嵌套属性不会被递归代理。
- **场景**：性能优化，避免不必要的深层响应式开销。
- **示例**：
  ```javascript
  const state = shallowReactive({ count: 0, user: { name: 'Vue' } });
  
  state.count++; // 触发响应式更新
  state.user.name = 'React'; // 不触发响应式更新
  ```

---

### 4. **`toRaw`**
- **作用**：获取由 `reactive` 或 `readonly` 创建的代理对象的原始对象。
- **语法**：
  ```javascript
  const rawObject = toRaw(proxyObject);
  ```
- **特点**：
  - 返回的对象是非响应式的。
- **场景**：需要移除响应式特性时使用。
- **示例**：
  ```javascript
  const state = reactive({ count: 0 });
  const rawState = toRaw(state);
  
  console.log(rawState); // 输出: { count: 0 }
  ```

---

### 5. **`markRaw`**
- **作用**：标记一个对象使其永远不会被转换为响应式。
- **语法**：
  ```javascript
  const rawObject = markRaw(object);
  ```
- **特点**：
  - 即使将该对象传递给 `reactive`，它也不会变为响应式。
- **场景**：性能优化，避免某些大型或静态对象被代理。
- **示例**：
  ```javascript
  const rawObject = markRaw({ count: 0 });
  const state = reactive(rawObject);
  
  console.log(isReactive(state)); // 输出: false
  ```

---

| `unref`           | 解包 `ref` 类型的值                      | 统一处理可能为 `ref` 的值        |
| `isRef`           | 判断是否是 `ref`                         | 区分 `ref` 和普通值              |
| `toRef`           | 从响应式对象中提取单个属性并转换为 `ref` | 单独操作某个属性                 |
| `toRefs`          | 将响应式对象的所有属性转换为 `ref`       | 解构响应式对象时保留响应性       |
| `reactive`        | 创建深层响应式的对象                     | 管理复杂状态对象                 |
| `isReactive`      | 判断是否是响应式对象                     | 区分响应式对象和普通对象         |
| `shallowReactive` | 创建浅层响应式的对象                     | 性能优化，避免深层响应式开销     |
| `toRaw`           | 获取响应式对象的原始对象                 | 移除响应式特性                   |
| `markRaw`         | 标记对象使其永远不会被转换为响应式       | 避免某些对象被代理               |
| `readonly`        | 创建只读的响应式对象或 `ref`             | 确保状态不可被修改               |
| `shallowReadonly` | 创建浅层只读的响应式对象                 | 性能优化，避免深层属性的只读检查 |

## toRefs、toRef 和 toRaw对比总结

| 方法名   | 输入类型            | 输出类型            | 使用场景                                                     |
| -------- | ------------------- | ------------------- | ------------------------------------------------------------ |
| `toRefs` | 响应式对象          | 包含多个`ref`的对象 | 对响应式对象进行解构时，保持响应式特性                       |
| `toRef`  | 响应式对象 + 属性名 | 单个`ref`           | 提取响应式对象的单个属性，并保持响应式特性                   |
| `toRaw`  | 响应式对象          | 普通对象            | 获取响应式对象背后的原始数据，用于性能优化或与非响应式代码交互的场景 |

## **对比 `fill` 和 `padding`**

| 特性               | `fill(value, start, end)`  | `padStart(targetLength, padString)`<br />`padEnd(targetLength, padString)` |
| ------------------ | -------------------------- | ------------------------------------------------------------ |
| **作用对象**       | 数组                       | 字符串                                                       |
| **是否改变原对象** | 改变原数组（原地操作）     | 不改变原字符串（返回新字符串）                               |
| **用途**           | 填充数组元素               | 在字符串开头或结尾添加填充字符                               |
| **参数**           | 填充值，起始索引，结束索引 | 目标长度，填充字符                                           |
