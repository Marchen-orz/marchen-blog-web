缓存不是“越多越快”，而是把正确的数据放在正确的位置，并知道什么时候让它失效。

## 为什么需要缓存

网络、磁盘和数据库查询都有成本。缓存可以复用昂贵计算的结果，也可以让用户在弱网络环境下仍然得到可接受的体验。

## 缓存层级

1. 浏览器内存缓存，适合短生命周期的小资源。
2. HTTP 缓存，依赖 `Cache-Control`、`ETag` 和 CDN。
3. 应用缓存，常见于 Redis 或本地 LRU。
4. 数据库缓存，通常是查询计划、页缓存或物化视图。

```ts
const cacheKey = `user:${userId}`;
const cached = await redis.get(cacheKey);

if (cached) {
  return JSON.parse(cached);
}

const user = await db.user.findUnique({ where: { id: userId } });
await redis.set(cacheKey, JSON.stringify(user), { EX: 60 });
return user;
```

## 实践清单

- 先定义缓存的数据边界，再选择缓存位置。
- 失效策略要比“缓存多久”更重要。
- 给缓存 key 加版本号，避免结构变化造成脏读。
- 监控命中率、延迟和回源量。

缓存的目标不是让系统看起来复杂，而是让用户更稳定地获得结果。
